Headerwise 可以在 Chrome 和 Edge 中修改 HTTP 请求头和响应头。设置、追加或删除请求头，把它们分组到配置文件中，只在需要的地方启用。

一切都在你的浏览器内完成。无需账号，没有统计分析，扩展也无法向任何地方发送任何数据：它的清单文件禁止网络连接，浏览器本身会拦截这些请求。请求头的修改由浏览器通过 declarativeNetRequest 执行，因此 Headerwise 从不读取你访问的页面。

你可以做什么
• 请求头和响应头：按配置文件设置、追加或删除。
• 配置文件：数量不限，可同时启用多个。可复制、拖动排序（两个配置文件修改同一请求头时，靠左的优先），也可用快捷键切换。
• 过滤：按 URL 模式或正则表达式“仅在 / 从不在”生效；仅对某些网站发起的请求、某些请求类型（页面、fetch/XHR、脚本等）或请求方法生效；或仅在一个标签页中生效。
• 重定向：替换地址中的一部分，例如把发往 api.example.com 的请求转到你的测试服务器。
• 当前标签页：打开弹出窗口即可查看当前页面上哪个配置文件修改了多少个请求，以及另一个为什么没有生效。
• 从 DevTools 粘贴：把请求复制为 cURL、fetch 或 PowerShell，粘贴后勾选需要的请求头。
• 预设：CORS、移除 Content-Security-Policy、允许网站在 iframe 中打开、Bearer 令牌、禁用缓存、iPhone 或 Googlebot 的 User-Agent 等。
• 变量：{{uuid}}、{{timestamp}}、{{date}} 等，每次修改时填入，并每分钟更新一次。
• 敏感信息自动隐藏：令牌和 Cookie 显示为圆点，点击眼睛图标才会显示，共享屏幕时更安心。
• 以 JSON 导出和导入配置文件。除非你主动选择，否则不包含敏感值。
• 浅色和深色主题。

从 MODHEADER 迁移？
ModHeader 已于 2026 年 7 月从 Chrome 和 Edge 的商店下架。如果浏览器停用了它，导出按钮也就无法使用了，但你的配置文件仍保存在磁盘上。Headerwise 可以直接在页面中读取 ModHeader 的文件夹（不会上传任何内容），连同过滤规则、重定向和 Cookie 规则一起迁移配置文件。从 ModHeader 导出的 JSON 文件同样可以导入。

为什么不直接用 DEVTOOLS？
DevTools 很适合查看请求头，但它无法给所有请求添加 Authorization 这类请求头，而且它的覆盖功能只在该标签页打开 DevTools 时有效。Headerwise 在所有标签页中持续生效，直到你暂停它。
